- Step 1.5a: delivery origin (`Dam.Delivery`) with HMAC-signed, expiring, scope- and IP-bound links (`POST /assets/{id}/links`), on-the-fly image transforms (libvips: w/h/fit/fmt/q/focal) with tamper protection, cached renditions with deterministic keys, ETag/Cache-Control/`X-Dam-Cache`, watermarking for unpublished assets, image profiles (thumb, preview, web, web_jpeg, mobile) generated on ingest, `GET /assets/{id}/renditions`, ADR-0006. Video, PDF and Office renditions follow in 1.5b.
- Step 1.5b: video renditions (FFmpeg: poster/thumb stills, preview/mobile/signage_1080/signage_4k transcodes, H.264 throughout), PDF page renditions (Poppler: thumb/preview from page 1, `pdf_pages-{n}` for every page up to a configurable limit), HTTP range requests on the delivery origin for video seeking, ADR-0007. An unpublished video refuses its (unwatermarked) video renditions by link rather than leak them. Office document (DOCX/PPTX/XLSX) conversion is deferred to Step 1.5c. Test infra: the shared test SeaweedFS container now sets `-volume.max=100` (it was silently refusing writes once it hit its default volume-count cap, the same symptom the dev compose stack's S3 service was fixed for earlier).
- Step 1.5c: Office document renditions (DOCX/PPTX/XLSX → PDF via LibreOffice headless, then the existing PDF rendition pipeline: thumb/preview from page 1, `pdf_pages-{n}` per page). Content sniffing now identifies DOCX/PPTX/XLSX from their ZIP entries rather than trusting the file extension. ADR-0008. Completes Step 1.5 (renditions and delivery).
- Step 1.6a: lifecycle transitions (submit, approve, reject, publish, withdraw, expire, archive) as a state machine with permission, required-metadata and workflow-approved guards (`POST /assets/{id}/transitions/{action}`); version restore (`POST /assets/{id}/versions/{v}/restore`) copies an old version's bytes into a new one rather than rewriting history; version comparison (`GET /assets/{id}/versions/{v}/compare/{other}`) reports what changed. ADR-0009. Scheduled publish/expire and retention policies follow in Step 1.6b.
- Step 1.6b: scheduled publish/expire (`POST /assets/{id}/schedule`, a poller job with a ~15s SLA) and retention policies (`/retention-policies` CRUD, auto-archive and auto-purge with an hourly job, legal hold via `POST /assets/{id}/legal-hold`, `POST /assets/{id}/retention-policy`). Purge deletes the asset's underlying file bytes, not just its status. ADR-0010. Completes Step 1.6 (versioning, lifecycle, retention).
- Step 1.7a: OpenSearch index per tenant (`dam-{tenant}-assets`, addressed through a write alias) with a mapping generated from each asset type's current metadata schema (searchable/facet flags, multilingual analyzers for en/hi/mr/ta/te + generic, nested resolved taxonomy terms, k-NN vector placeholders for Step 2.1's semantic search); `IndexConsumer` keeps it in sync with asset events; `SearchReindexJob` rebuilds a tenant's index from scratch and swaps it in with zero downtime (alias swap). ADR-0011. The query surface (`POST /search`, suggest, facets, saved searches) follows in Step 1.7b.
- Step 1.7b: `POST /search` (query, filters, facets, sort, highlight, `similarTo`) and `GET /search/suggest` replace `ListAssetsHandler`'s in-memory row filtering with a real query, translating the caller's ABAC scope clauses into an OpenSearch filter (`AccessQueryTranslator`) so search enforces exactly what the policy engine does; `GET /facets` returns value counts across the whole visible corpus. Cursor pagination via `search_after`. ADR-0012. Saved searches (`Collection`, spec A4.1) follow in Step 1.7c.
- Step 1.7c: saved searches (`Collection`, spec A4.1) - static (explicit `assetIds`) and smart (a saved search, re-run on demand) collections; `/collections` CRUD, `POST /collections/{id}/assets` (add/remove, static only), `POST /collections/{id}/share` (private/tenant visibility), `GET /collections/{id}/assets` resolves either kind's contents through search itself. A static collection's real membership now feeds `collection_ids` in the search index (`TenantCollectionIndex`, `IndexConsumer` reacting to `collection.assets_changed`), so a collection-scoped access rule - accepted since Step 1.1 but dead until now - genuinely narrows search results. ADR-0013. Completes Step 1.7 (search and indexing).

ADR-0014. Upload, asset detail, bulk edit/collections UI and the Playwright e2e suite follow in 1.8b-e.
