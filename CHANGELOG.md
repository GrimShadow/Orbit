# Changelog
## Unreleased
- Step 0.1: repo layout, tooling, CI skeleton.
- Step 0.2: Docker Compose dev stack (Mac-friendly profiles), Keycloak realm, ADR-0001 (SeaweedFS instead of MinIO).
- Step 0.3: domain primitives (Entity, AggregateRoot, UUID v7, Result<T>) and command pipeline (validation, authorization, transaction, outbox).
- Step 0.4: EF Core 9 persistence, tenant query filter + Postgres RLS (forced), outbox, hash-chained append-only audit_log, Testcontainers integration tests; `make migrate`.
- Step 0.5: API host (Keycloak JWT, tenant/user from claims, problem+json, correlation IDs, OpenTelemetry, health, rate limiting, OpenAPI); realm now emits sub/email/tenant (UUID)/roles claims.
- Step 0.6: RabbitMQ topology (per-consumer queues, tiered retry, DLQ), outbox relay (restricted dam_system role), idempotent consumer host, Quartz-backed IJobScheduler, Worker and Scheduler hosts, `POST /api/v1/system/ping`.
- Step 0.7: UI kit (tokens, light/dark, 11 accessible components, Storybook), console shell (Keycloak OIDC+PKCE, TanStack Query, i18n en/hi, tenant switcher, user menu, error boundary), ESLint+Prettier, Keycloak realm: refresh rotation and post-logout redirect.
- Step 0.8: CI (build, test, lint, CodeQL, Semgrep, Trivy fs+image, CycloneDX SBOMs, helm lint), multi-arch GHCR images by git SHA, nightly stack smoke + ZAP, Dependabot, Dockerfiles (non-root), `tools/smoke.sh`.
- CI first-run fixes: actions pinned by commit SHA, Trivy from a digest-pinned container, CodeQL gated in-job (no paid upload), nginx security headers at server level, favicon file, pnpm 10 with release-age/trust safeguards, Dependabot cooldown.
- Step 1.1: tenants, users, groups, roles, access rules; RBAC+ABAC policy engine (ADR-0002) with 388 unit cases; JIT provisioning from Keycloak tokens; admin API (users, groups, roles, access rules, tenant); tenants RLS; realm dev users; console account page; `tools/demo-identity.sh`.
- Step 1.2: folders (ltree-style paths, scoped permissions, inherited metadata), vocabularies and terms, versioned metadata schemas with a validation engine, template packs (`core`, `automotive-sample`), ADR-0003. Product renamed to Orbit; client-specific sample content removed.
- Step 1.3: assets (shells with validated metadata, derived access attributes), resumable direct-to-S3 multipart uploads with presigned URLs, worker-side SHA-256 hashing and duplicate detection, bulk upload, asset access control (ADR-0004), `tools/upload-demo.sh`.
- Step 1.4: ingest pipeline (scan → sniff → extract → promote → perceptual hash) as a chain of idempotent consumers, ClamAV INSTREAM scanning that fails closed, content sniffing (executables always refused), technical metadata (image/PDF/Office/ffprobe), asset versions with multipart-copy promotion, `GET /assets/{id}/versions` and `/similar?by=phash`, ADR-0005. Duplicate multipart parts are now resolved by ETag, then size, then time.
- Step 1.5a: delivery origin (`Dam.Delivery`) with HMAC-signed, expiring, scope- and IP-bound links (`POST /assets/{id}/links`), on-the-fly image transforms (libvips: w/h/fit/fmt/q/focal) with tamper protection, cached renditions with deterministic keys, ETag/Cache-Control/`X-Dam-Cache`, watermarking for unpublished assets, image profiles (thumb, preview, web, web_jpeg, mobile) generated on ingest, `GET /assets/{id}/renditions`, ADR-0006. Video, PDF and Office renditions follow in 1.5b.
- Step 1.5b: video renditions (FFmpeg: poster/thumb stills, preview/mobile/signage_1080/signage_4k transcodes, H.264 throughout), PDF page renditions (Poppler: thumb/preview from page 1, `pdf_pages-{n}` for every page up to a configurable limit), HTTP range requests on the delivery origin for video seeking, ADR-0007. An unpublished video refuses its (unwatermarked) video renditions by link rather than leak them. Office document (DOCX/PPTX/XLSX) conversion is deferred to Step 1.5c. Test infra: the shared test SeaweedFS container now sets `-volume.max=100` (it was silently refusing writes once it hit its default volume-count cap, the same symptom the dev compose stack's S3 service was fixed for earlier).
- Step 1.5c: Office document renditions (DOCX/PPTX/XLSX → PDF via LibreOffice headless, then the existing PDF rendition pipeline: thumb/preview from page 1, `pdf_pages-{n}` per page). Content sniffing now identifies DOCX/PPTX/XLSX from their ZIP entries rather than trusting the file extension. ADR-0008. Completes Step 1.5 (renditions and delivery).
- Step 1.6a: lifecycle transitions (submit, approve, reject, publish, withdraw, expire, archive) as a state machine with permission, required-metadata and workflow-approved guards (`POST /assets/{id}/transitions/{action}`); version restore (`POST /assets/{id}/versions/{v}/restore`) copies an old version's bytes into a new one rather than rewriting history; version comparison (`GET /assets/{id}/versions/{v}/compare/{other}`) reports what changed. ADR-0009. Scheduled publish/expire and retention policies follow in Step 1.6b.
- Step 1.6b: scheduled publish/expire (`POST /assets/{id}/schedule`, a poller job with a ~15s SLA) and retention policies (`/retention-policies` CRUD, auto-archive and auto-purge with an hourly job, legal hold via `POST /assets/{id}/legal-hold`, `POST /assets/{id}/retention-policy`). Purge deletes the asset's underlying file bytes, not just its status. ADR-0010. Completes Step 1.6 (versioning, lifecycle, retention).
- Step 1.7a: OpenSearch index per tenant (`dam-{tenant}-assets`, addressed through a write alias) with a mapping generated from each asset type's current metadata schema (searchable/facet flags, multilingual analyzers for en/hi/mr/ta/te + generic, nested resolved taxonomy terms, k-NN vector placeholders for Step 2.1's semantic search); `IndexConsumer` keeps it in sync with asset events; `SearchReindexJob` rebuilds a tenant's index from scratch and swaps it in with zero downtime (alias swap). ADR-0011. The query surface (`POST /search`, suggest, facets, saved searches) follows in Step 1.7b.
- Step 1.7b: `POST /search` (query, filters, facets, sort, highlight, `similarTo`) and `GET /search/suggest` replace `ListAssetsHandler`'s in-memory row filtering with a real query, translating the caller's ABAC scope clauses into an OpenSearch filter (`AccessQueryTranslator`) so search enforces exactly what the policy engine does; `GET /facets` returns value counts across the whole visible corpus. Cursor pagination via `search_after`. ADR-0012. Saved searches (`Collection`, spec A4.1) follow in Step 1.7c.
- Step 1.7c: saved searches (`Collection`, spec A4.1) - static (explicit `assetIds`) and smart (a saved search, re-run on demand) collections; `/collections` CRUD, `POST /collections/{id}/assets` (add/remove, static only), `POST /collections/{id}/share` (private/tenant visibility), `GET /collections/{id}/assets` resolves either kind's contents through search itself. A static collection's real membership now feeds `collection_ids` in the search index (`TenantCollectionIndex`, `IndexConsumer` reacting to `collection.assets_changed`), so a collection-scoped access rule - accepted since Step 1.1 but dead until now - genuinely narrows search results. ADR-0013. Completes Step 1.7 (search and indexing).
- Step 1.8a: `@dam/sdk-js` is now a real typed API client generated from `docs/api/openapi.json` (`openapi-typescript` + `openapi-fetch`), replacing the console's hand-rolled `apiFetch`; console library screen (folder tree + asset grid/list with status/type filters and pagination) wired to real `GET /folders` and `GET /assets`. ADR-0014. Upload, asset detail, bulk edit/collections UI and the Playwright e2e suite follow in 1.8b-e.
- Step 1.8b: console upload screen - a drag-drop zone (also a plain, always-usable file input) plus a batch metadata form (folder, tags), driving `POST /assets/bulk-upload` (one draft asset + one upload per file) and each file's own multipart transfer straight to storage, with live per-file progress and the ingest pipeline's own terminal status (ready/duplicate/blocked/failed) once each upload completes. `make openapi` now also regenerates `@dam/sdk-js`'s generated client, fixing (and preventing a repeat of) a stale schema that was silently missing every upload endpoint. ADR-0015.
- Step 1.8c: console asset detail page (`/library/assets/:id`, reachable from both library views) - a preview player for image/video/PDF via signed delivery links, a metadata form generated from the asset type's current schema (including multilingual fields across en/hi/mr/ta/te and a flattened vocabulary/term-tree picker), lifecycle action buttons driven by the same transition table as the backend state machine, and a versions panel with restore. "Rights" is explicitly out of scope - no backend for it exists yet. ADR-0016.
- Step 1.8d: console bulk edit - multi-select in both the library grid (`ThumbnailGrid`) and list (`Table`, which gained the same optional selection contract) view, plus a bulk edit bar to add/remove tags, move to a folder, or run a lifecycle transition (only ever offering actions valid for every selected asset) across the whole selection at once. There is no backend bulk-edit endpoint (confirmed - only per-asset `PATCH`/`move`/`transitions` exist), so this fans the same calls out over a small fixed-concurrency pool (`bulkOrchestrator.ts`, same shape as 1.8b's upload batching) instead. ADR-0017. Collections/saved-searches UI (also originally scoped into 1.8d by the spec) moves to Step 1.8e; the keyboard-shortcuts/mobile/e2e work planned as 1.8e is renumbered 1.8f.
- Step 1.8e: console search page (`/search`, `POST /search` with a text query, type/status facets, and cross-folder results - distinct from the library screen's folder-scoped browsing), collections list and detail pages (`/collections`, `/collections/:id` - rename, share visibility, delete, paginated contents for both static and smart collections through the same `GET /collections/{id}/assets`), and saved searches (just a named smart collection - "Save this search" on the Search page, "Save as collection" reusing 1.8d's bulk selection for a static one). First console use of `ui-kit`'s `Modal`/`FacetList`/`useToast`. ADR-0018. Completes Step 1.8's original screen list (1.8a-1.8e); keyboard shortcuts/mobile-responsive/Playwright e2e remain as 1.8f.
- Step 1.8f: console keyboard shortcuts (single-key nav shortcuts for library/search/collections/upload, a `?` help dialog reachable by key or a visible header button, never hijacking typing in a form control) and a mobile-responsive CSS audit (fixed a missing `flex-wrap` on collection list rows; every other screen already wrapped correctly from earlier steps' patterns). ADR-0019. Playwright e2e against the real stack is split out further as Step 1.8g (needs `docker compose` up, not just frontend code).
- Step 1.8g: Playwright e2e suite (`tests/e2e/`, run against the real dev stack - see its README) covering the spec's Step 1.8 accept criterion end to end: upload → edit metadata → publish → appears in search with correct facets, and a 50-asset bulk edit under 5 seconds; a separate suite checks every primary screen at 390px width. ADR-0020. Running it for real found and fixed two genuine console bugs the CSS-only 1.8f audit missed - `box-sizing: border-box` was never set anywhere in the design system (added globally), and `.dam-nav` had no `flex-wrap` (six links now overflowed 390px once Step 1.8e added two more) - plus two environment-only issues (stale long-running `Dam.Api`/`Dam.Worker` dev processes; a stale OpenSearch `create_index` block from a full Docker disk), documented for whoever hits them next. **Completes Step 1.8 (the console) in full.**
